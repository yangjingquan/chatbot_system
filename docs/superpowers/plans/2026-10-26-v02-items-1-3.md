# 培训客服 v0.2 编号 1–3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 完成用户已确认的多轮意向状态、员工与权限、知识版本及有效性三项优化。

**Architecture:** 保留现有 FastAPI/React/PostgreSQL 结构。意向按消息时序维护多个考试需求；角色与对象范围在服务端统一执行；知识草稿、审核及发布修订独立于正式检索快照，通过兼容迁移保留既有资料和对话。

**Tech Stack:** 现有 Python、SQLAlchemy、React、TypeScript 与 Docker，无新增外部服务。

**Spec:** 用户本轮确认的编号 1–3，及本计划下述约束；不涉及后续课程班次、独立学员 CRM、完整分页、预约与公网部署。

## Global Constraints
- 保留现有数据库、管理员、企业资料、对话及已配置的 DeepSeek Key；不输出密钥，不删除卷，不使用付费模型执行自动测试。
- 角色：admin 全部；knowledge 知识草稿/提交/历史/检索；support 全机构咨询接待及线索查看/跟进；advisor 仅分配给自己的线索和关联咨询。只有 admin 可分配、导出、发布/撤回/回滚知识及管理员工。
- 新知识运营提交草稿后由管理员审核；管理员可以直接发布自己的草稿。发布后的修订不可原地编辑，修改形成新草稿；审核和版本变动有审计。
- 政策知识发布需指定考试、年度、地区及已核对的 HTTP(S) 来源；未明确年度/地区的问题不检索有特定年度/地区限制的政策。过期和未生效知识不得进入公众检索、历史重放和模型上下文。
- 停止联系只有再次明确提交联系许可才能恢复；新的普通提问不改变联系许可。购买意愿与联系许可分别处理。
- 沿用既有界面风格；新增员工页、知识历史/审核界面和权限感知导航，所有界面与 API 同步更新。

## Review Focus
- 取消之后的谢谢/中性消息、重新明确购买、同时备考与更换考试，不恢复旧分数或混用售后目的。
- 用其他员工的 ID 绕过列表进入详情、关联会话、跟进、导出或统计，必须失败；禁用/变更角色和密码重设立即影响旧会话。
- 最后一个可用管理员不能被禁用或降权，旧演示的文字负责人不得错误绑定同名员工。
- 编辑/待审核不会改变公开答案；审核中的草稿不可偷偷替换；并发编辑/审核检查修订序号；回滚建立新修订并原子更新索引。
- 日期边界、年度与地区缺失、撤回后历史、政策来源验证，以及重复启动迁移都保持一致。
