**Architecture:** 保留 FastAPI / React / PostgreSQL。增加结构化课程班次和学员关系；公众课程事实只取有效业务数据；统一查询层供分页、导出和看板使用。

## Global Constraints
- 保留现有业务数据、员工和 DeepSeek Key；先备份，增量幂等迁移；自动验收禁用付费模型。
- 管理员维护课程及班次；其他接待岗位可读取。知识运营可读取课程以维护资料，不能改价。学员权限继承现有接待范围，管理员负责分配和合并。
- 一个学员可关联多条咨询线索、考试目标和课程需求。联系方式只给出疑似重复提醒；不自动绑定或合并，合并须人工确认身份与原因，不合并各次联系许可。
- 学员及其关联线索采用同一负责人；调整已关联线索负责人时同步学员与关联线索，并明确告知。旧线索不凭未核验联系方式自动建联。
- 日期筛选按北京时间创建日期，起止日期均包含。列表、CSV 和统计共用相同筛选及权限。页大小最多 100，CSV 不受页大小和旧 500 条限制。
- 不扩展原清单第 7–10 项的预约、复杂人工坐席、质量成本平台、检索扩容和公网发布。

## Interfaces
- Course / CourseBatch：考试、班型、课时、授课方式、开班安排、售价（整数分）、价格有效期、停售状态、修订序号。
- /admin/courses、/admin/courses/{id}/batches CRUD；结构化课程源与历史有效性校验，过期价格及停售课程不能使用旧文档报价。
- Student / StudentInterest（联系方式从关联 Lead 投影） + Lead.student_id / next_followup_at / contact_hash；/admin/students、/leads/{id}/student、/students/{id}/merge、/admin/todos。
- BusinessFilters -> lead_query / conversation_query / student_query；分页统一 {items,total,page,page_size,pages}。日期、考试、负责人、阶段、意向、联系许可及关键字过滤。
- 所有前端列表、导出地址、统计和现有测试脚本同步适配分页契约。

## Review Focus
- 更新价格、停售、价格过期后，公众新回答、历史重放与模型上下文均不再出现旧价格；政策检索仍保持年度地区隔离。
- 未核验同联系方式只提示；学员合并不能把停止联系变为可联系；顾问不能通过学员、重复候选、关联咨询或合并读取他人数据。
- 两个管理员并发关联/合并/改价不得相互覆盖；同学员负责人同步且旧员工立即失去访问范围。
- 300+ 会话、500+ 线索跨页无丢失/重复；导出条数和统计等于全量筛选结果；北京时间边界及演示排除一致。
- 停止联系在列表突出展示，跟进待办不提醒对已撤回许可的线索外呼。
