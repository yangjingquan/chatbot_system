# v0.4：接待、质量与任务可靠性

依据：用户批准的原清单第 7、8、9 项；单机构自用，保留租户隔离，沿用 DeepSeek 和现有权限。不得覆盖本地密钥、重置数据库或公开部署。

## Task 1: 人工接待与试听预约（7）
接口：现有会话、线索、课程；新增在线心跳、排队时间、已读水位和试听记录。接待操作须锁定并重新检查权限；转交不改变线索归属，顾问只能接待本人范围。试听为待确认申请，客服确认后才生效。
步骤：先写在线/并发接管/转交范围/未读/试听状态与访客隔离测试并观察失败；实现 API 与管理、访客界面；运行相关测试。Expected: 全部通过。

## Task 2: 回答质量、反馈与用量（8）
接口：Message、流式模型调用、知识草稿、角色权限。负反馈与未知问题进入可处理缺口；人工创建草稿后仍须原审核发布。评测覆盖五类问题，自动检索检查和人工回答验收分开。供应商错误只展示安全分类；用量记录失败及未知用量，价格需管理员配置后估算，预算仅站内告警。
步骤：先写反馈所有权/缺口/模型错误/费用与预算/评测人工标注测试并观察失败；实现后台与访客操作；运行相关测试。Expected: 全部通过。

## Task 3: 数据库检索与持久任务（9）
接口：知识发布、切片、PostgreSQL、工作进程、上传 UI。数据库先过滤有效性和租户再排名，不限制前 5000 条。同步原子切换发布文字索引，后台任务补充向量；解析异步生成草稿。任务有进度、租约、失败原因、有限重试；更新版本时旧任务不得覆盖。独立 worker 容器持久消费。
步骤：先写超过 5000 条命中/过滤/失败重试/租约恢复/旧版本保护测试并观察失败；实现和接入；完整后端与前端测试、真实 PostgreSQL 并发测试和浏览器回归。Expected: 全部通过。

## Review Focus
跨员工接待与顾问数据隔离；访客伪造反馈/预约；并发转交、确认与任务重复消费；任务处理中发布/下架；未配置价格和失败调用不能伪报零成本；自动评测不能被展示为模型准确率；长期运行 worker 的恢复。

## 验证与交付
保留迁移前私有备份；不调用付费模型作大批量自动评测；一次独立整体验证评审，重要问题补回归测试；构建并启动本地容器，提交代码及完整验收记录。
