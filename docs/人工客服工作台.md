# 人工客服工作台（第 8 项）

## 已实现

- **工作量**：`/admin/reception-staff` 返回每位接待人的 `active_count` / `max_active` / `at_capacity`。
- **分配规则**：企业配置 `reception_assign_mode`=`least_busy`（**默认**，最少负载优先）或 `manual`（手动领取）；可在「机器人配置」改回 `manual`。`reception_max_active` 限制同时接待数；支持「接下一位」领取最久/超时排队。
- **等待时长与超时**：会话带 `waiting_seconds`、`timed_out`；摘要含 `timed_out`、`oldest_wait_seconds`、`timed_out_ids`。阈值由 `reception_wait_timeout_seconds`（默认 **300**）配置。
- **常用回复**：配置于机器人设置 `canned_replies`，咨询页一键填入；`GET /admin/canned-replies`。
- **交接备注**：转交时可写 `note`，写入会话 `handoff_note` 并在详情展示。
- **防重复接管**：接管使用行锁 + `UPDATE … WHERE assigned_to_id IS NULL OR = self`，并发时仅一人成功（另一人 409）；幂等自接管返回 200。
- **防丢消息**：人工回复支持 `client_id` 幂等；访客侧原有消息幂等不变。
- **WebSocket 实时推送**（本轮补齐）：
  - 路径：`WS /api/admin/reception/ws`（经 `web` 反代时同源 `/api/admin/reception/ws`）。
  - 鉴权：与后台相同的 `admin_session` Cookie；须具备 `conversations.read`；未登录关闭码约 `4401`。
  - 事件（租户隔离）：`queue.waiting`、`conversation.taken`、`conversation.transferred`、`conversation.closed`、`conversation.returned`、`message.user`、`message.agent`，以及心跳 `ping`/`pong`/`connected`。
  - 前端：接待摘要与咨询列表/详情**优先**用 WS 触发刷新；WS 不可用时回退原轮询（摘要 15s、列表 5s、详情 2.5s）；WS 连通时轮询降频作兜底。
  - **局限**：进程内内存广播，适合本机单 `backend` 副本；多 uvicorn worker / 多 backend 容器之间不共享事件，需另接共享总线。

## 分配规则说明

| 模式 | 含义 |
| --- | --- |
| `least_busy`（默认） | 「接下一位」时，若有更空闲的在线客服，非管理员会被 409 提示让对方优先；按在线接待数最少者优先。 |
| `manual` | 任一有权限且未达上限的客服都可主动领取/接管，不比较彼此负载。 |

## 配置入口

后台「机器人配置」：分配规则、接待上限、排队超时秒数、常用回复（标题 Tab 正文）。
