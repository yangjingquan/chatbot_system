# 统计口径与系统性能（第 13 项）

## 统一指标口径

列表、CSV 导出与 `/admin/overview` 共用 `BusinessFilters`（日期按 Asia/Shanghai 日界、演示过滤、考试/负责人/阶段/等级/联系许可/关键词）。默认 **不包含演示数据**（`include_demo=false`）。

| 指标 | 字段 | 定义 |
| --- | --- | --- |
| 有效咨询 | `counts.conversations` | 至少发过一条用户消息，**或**提交过联系请求的会话；仅打开面板不计 |
| 留资线索 | `counts.leads` | 自愿提交联系方式形成的线索条数；与线索列表 `total`、导出行数一致 |
| 留资会话 | `counts.contacted_conversations` | 有效咨询中已有线索记录的会话数；留资率 = 本值 ÷ 有效咨询 |
| 试听 | `counts.trials` | 有效咨询关联的试听申请条数（含待确认/已确认/已参加/未参加/已取消） |
| 成交 | `counts.customers` | 线索阶段为「已成交」；依赖顾问回填，非机器人推断 |
| 合格及以上 | `counts.qualified` | 阶段为已合格、商机推进或已成交 |
| 高意向 | `counts.high_intent` | 等级为「高意向」；仅作跟进辅助，非成交概率 |
| 待跟进 | `counts.pending` | 阶段为新线索或待分配 |
| 转人工排队 | `counts.handoffs` | 有效咨询中当前 `status=waiting` 的会话数 |
| 人工首次回复时长 | `reply_latency` | 有 `waiting_since` 且存在客服消息时，排队时刻 → 首条 `role=agent` 的平均秒数；无样本为 `null` |

API 同时返回 `metric_definitions` 文本，便于后台展示与对外说明对齐。

## 实现要点

- 概览计数、趋势、意向/考试分布、Token 用量、知识缺口改为数据库聚合，避免把全量会话/消息载入应用内存。
- 接待摘要的未读总数、排队/超时改为一次（或少量）SQL，不再对每个会话循环 `unread()`。
- 咨询列表预览用「最后一条 + count」查询，详情仍加载完整 transcript。

## 自测与基准

```bash
# 口径一致性 + 未读汇总 + 合成 600 条微基准（SQLite，非生产压测）
docker compose run --rm -v "$PWD/backend:/app" -e DATABASE_URL=sqlite:////tmp/analytics-test.db \
  -e REDIS_URL= -e EMBEDDING_ENABLED=false -e DEEPSEEK_API_KEY= \
  backend python -m pytest tests/test_analytics.py tests/test_queries.py -q -s
```

说明：上述命令用挂载源码与临时 SQLite，便于改完即测；**不是**约定生产数据量下的 PostgreSQL 压测。大规模真实压测需在接近日咨询量的库上复测检索、导出与多客服接待，并记录 CPU/内存；本项仅保证可复现的合成路径与口径一致。

## 局限

- 导出 CSV 仍会物化筛选后的线索行；超大导出可再改为流式游标。
- 考试分布按线索标签/关联会话分析逐考试计数，考试字典增大时成本近似 O(|EXAMS|)。
- 人工回复时长只统计「排队 → 首条客服消息」，不含机器人首答延迟。
