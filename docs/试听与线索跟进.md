# 试听与线索跟进（第 9 项）

## 业务链

咨询会话 → 自愿留资（线索）→ 申请试听 → 确认/参加/未参加/取消 → 跟进待办 →（人工）关联学员、改阶段。

试听详情 `GET /admin/trials/{id}` 直接返回线索摘要、学员摘要、最近跟进记录，以及「自动待办说明 / 需人工确认事项」。线索详情与学员档案也会列出关联试听。

## 状态

| 状态 | 含义 |
| --- | --- |
| pending | 待确认 |
| confirmed | 已确认时间与顾问 |
| attended | 已参加 |
| no_show | 未参加（须填原因） |
| cancelled | 已取消（须填原因） |

允许变更：`pending → confirmed|cancelled`；`confirmed → confirmed|attended|no_show|cancelled`；终态误操作可填写更正原因后回到 `pending`，清除原确认安排并重新生成确认待办。提前记录参加必须明确确认并填写原因。

## 哪些操作自动生成待办

每条试听各自保存待办类型和时间，与线索人工设置的 `next_followup_at` 分开；待办页和工作台同时展示两种来源，可分别完成。试听状态变化只更新该试听自己的待办，并写入跟进记录。待办负责人沿用线索当前负责人；停止联系后不再提醒。不会自动改负责人、不自动创建/关联学员、不自动改成交阶段。

| 动作 | 自动待办时间 | 跟进文案要点 |
| --- | --- | --- |
| 访客申请试听 | 约 24 小时后 | 请确认时间与顾问；阶段若为「新线索/待分配」则改为「跟进中」 |
| 确认试听 | 等于确认上课时间 | 按时接待提醒 |
| 记录已参加 | 约 1 天后 | 试听后转化跟进 |
| 记录未参加 | 约 4 小时后 | 含未参加原因，尽快回访 |
| 取消预约 | 约 1 天后 | 含取消原因，确认是否继续跟进 |

## 哪些需要顾问人工确认

- 关联或新建学员档案（须核实同一人）
- 分配/改派线索负责人（确认试听不会自动改负责人）
- 参加后将线索推进到「商机推进 / 已成交」等阶段
- 取消或未参加后是否将线索标为「已失效」
- 联系许可撤回后的重新授权

试听详情中的 `manual_actions` 会按当前状态提示上述事项。

## 访客自助与通知

访客可对待确认或未来已确认的预约自行取消或申请改期；改期后回到待确认，顾问需重新确认。已到时间或已结束的预约需联系顾问。预约状态变更通过会话内持久消息告知，访客重新打开原咨询可查看。当前未接入短信、邮件或其他站外通知，不能保证访客离开后主动收到消息。

## 旧数据升级与备份

升级到数据库版本 15 时，系统按历史申请时间为待确认试听恢复确认待办，并按确认时间为已确认试听恢复接待待办；历史记录没有按试听保存的完成标识，无法准确判断旧待办是否已被完成。原线索跟进时间会保留，升级后请人工核查可能重复的提醒。已结束的旧试听不会自动重建待办。

逻辑 JSON 备份现有实现不包含试听预约，因此也不包含试听独立待办；恢复此类备份可能丢失这些数据。生产升级和恢复请使用包含完整数据库的 PostgreSQL 备份并验证恢复；逻辑备份不能替代完整数据库备份。
