# 知识库维护能力（第 11 项）

## 已实现

- **批量导入**：`POST /admin/document-jobs/upload-batch`（字段名 `files`，单次最多 30 个）。个别文件校验失败会记为失败任务，其余文件照常排队；前端知识库「批量上传」走此接口。
- **筛选**：文档任务支持 `status` / `kind` / `file_type` / `error_code` / `error_q`；知识列表增加 `visibility`（公开/内部）。
- **批量重试**：`POST /admin/document-jobs/retry-batch`。校验失败（类型/大小/空文件）不可重试，须重新上传；解析失败且未满 3 次可重试。
- **到期提醒与负责人待办**：`knowledge_todos` 表；访问 `/admin/knowledge-todos` 或工作台时同步。已发布且 `valid_until` 在 14 天内 → `expiring_soon`；已过期 → `expired`。负责人可标记完成；延长有效期或不再需要时系统自动关闭。
- **公开回答边界**：检索仍只取已发布、在有效期内、且 `visibility=public` 的资料（过期/内部不进入公开回答）。

## 单文件上限与 OCR

- 单文件上限由 **5 MB 调整为 15 MB**（`MAX_FILE_BYTES`）。理由：多页可复制文字的政策 PDF / 带表格 DOCX 常超过 5 MB；过大仍会占用任务 payload 与内存，故保留 15 MB 硬顶并有测试。
- **OCR 本版仍未启用**。扫描件或几乎无文字的 PDF 继续返回明确错误，提示改传可复制文字的 PDF / Markdown / TXT / DOCX。是否启用 OCR 待机构确认实际扫描资料比例后再定。
