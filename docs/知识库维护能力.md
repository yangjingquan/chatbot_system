# 知识库维护能力（第 11 项）

## 已实现

- **批量导入**：`POST /admin/document-jobs/upload-batch`（字段名 `files`，单次最多 30 个）。个别文件校验失败会记为失败任务，其余文件照常排队；前端知识库「批量上传」走此接口。
- **筛选**：文档任务支持 `status` / `kind` / `file_type` / `error_code` / `error_q`；知识列表增加 `visibility`（公开/内部）。
- **批量重试**：`POST /admin/document-jobs/retry-batch`。校验失败（类型/大小/空文件）不可重试，须重新上传；解析失败且未满 3 次可重试。
- **到期提醒与负责人待办**：`knowledge_todos` 表；访问 `/admin/knowledge-todos` 或工作台时同步。已发布且 `valid_until` 在 14 天内 → `expiring_soon`；已过期 → `expired`。负责人可标记完成；延长有效期或不再需要时系统自动关闭。
- **公开回答边界**：检索仍只取已发布、在有效期内、且 `visibility=public` 的资料（过期/内部不进入公开回答）。

## 单文件上限与 OCR

- 单文件上限为 **50 MB**（`MAX_FILE_BYTES`）；知识上传与 document-jobs 校验一致；`web`/`deploy` 反代 `client_max_body_size` 已放宽至约 55m。
- **OCR 已启用**（Docker 镜像内）：当 PDF 可复制文字不足时，使用 `pdf2image`（poppler）栅格化 + `pytesseract`（tesseract，`chi_sim+eng`）识别，最多 50 页、DPI 200。识别失败或仍无足够文字时返回明确 422，错误码归类为 `ocr`。
- 大扫描件 OCR 较慢：解析任务租约 **20 分钟**；请避免一次上传过多超大扫描 PDF。
- 系统依赖装在 `backend/Dockerfile`（backend 与 worker 同镜像）：`poppler-utils`、`tesseract-ocr`、`tesseract-ocr-chi-sim`、`tesseract-ocr-eng`。Python 包精确 pin：`pdf2image==1.17.0`、`pytesseract==0.3.13`。
