# 知行客服 · 培训机构智能客服系统

单企业自用的本地开发版，包含管理后台、培训机构官网演示和可嵌入官网的客服组件。覆盖公安联考、国考、省考、选调生、事业单位、社会招警、辅警及社区工作者咨询。当前为 v0.4 本地试用版，不代表原 10–12 周路线中的生产验收已经完成。

## 打开系统

- 管理后台：http://localhost:18080/
- 官网与悬浮客服：http://localhost:18080/demo
- 独立客服：http://localhost:18080/chat
- API 文档：http://localhost:18080/api/docs
- 课程与班次：http://localhost:18080/courses
- 学员档案：http://localhost:18080/customers
- 跟进待办：http://localhost:18080/todos

管理员邮箱默认 `admin@zhixing.local`；密码在本地 `.env` 的 `ADMIN_PASSWORD`。该文件由初始化脚本生成随机值，权限为 600，已加入 `.gitignore`。不要把 `.env`、真实联系方式或 Key 发到公开仓库。

## 启动与停止

需要 Docker Desktop 与 Docker Compose。首次启动：

```bash
python3 scripts/bootstrap.py
python3 scripts/generate_knowledge.py
docker compose up -d --build
```

`bootstrap.py` 保留已有 `.env`。Compose 使用 `zhixing_support` 独立命名空间、数据库和持久卷，唯一暴露端口默认只绑定本机 `127.0.0.1:18080`。不使用或修改其他项目数据库。

```bash
docker compose ps
docker compose logs --tail=60 backend
docker compose stop
docker compose start
```

停止不会删除资料。不要使用 `docker compose down -v`，除非确实要删除此项目的持久化数据库和模型缓存。日志可能包含业务错误和文件名，分享前检查脱敏。

## DeepSeek

在 `.env` 中配置：

```dotenv
DEEPSEEK_API_KEY=在此填写自己的Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

随后运行 `docker compose up -d --force-recreate backend`。Key 只在后端环境变量中使用，后台只返回“是否配置”，不会显示值。模型和参数根据 2026-10-26 核验的 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 实现；支持流式回答与用量记录，默认关闭思考模式以减少客服等待。

未配置 Key 时，界面和消息明确显示“资料摘录模式”；只返回实际找到的公开知识，不伪装为大模型回答。模型故障展示错误并保留检索来源，不隐藏失败。

## 知识与检索

`knowledge_base/` 包含 19 份演示 Markdown、`manifest.json` 及独立的初始验收样例 `evaluation.json`。18 份对外公开，1 份为内部权限测试资料。机构、价格、课程、员工、种子对话和联系方式都是合成设定，正式使用前必须替换审核。

首次启动幂等导入资料；之后修改文件不会覆盖后台现有版本。创建、上传及编辑均先保存为草稿，草稿与正式检索内容独立。知识运营提交审核后锁定，管理员可退回（须填写原因）或发布；管理员也可直接审核发布自己的草稿。支持 UTF-8 TXT/Markdown、文本型 PDF、DOCX，单文件 5 MB，正文不超过 20 万字符。扫描 PDF 会提示尚未启用 OCR。

向量使用本地 FastEmbed 的 `BAAI/bge-small-zh-v1.5`。PostgreSQL 用中文预分词、GIN 全文索引和数据库向量距离排名，再融合候选结果；有效性、租户、公开范围、年度和地区先在数据库过滤。SQLite 测试环境使用数据库文字排名。已去除前 5,000 个切片扫描限制，验证了超过此数量后的命中；尚未进行 10 万切片容量压测。模型首次下载保存在独立卷，不可用时使用文字检索。

公众检索只读取 `published + public` 且在有效期内的正式资料；年度、考试和地区限制必须与访客已明确的信息一致。具体考试政策发布须填写考试、年度、地区、HTTP(S) 来源，并人工确认已核对公告。通用说明可不限制年度。有效期按北京时间填写，留空不限制；过期、未生效、下架或内部资料不会进入公众检索。历史回答和模型上下文也会重新校验来源；跨地区或年度后的模型上下文会排除不再适用的旧答案。

每次发布形成版本历史，管理员可预览并回滚为新的正式版本；已有草稿须先处理后才能回滚。修改和审核采用修订序号检查，避免两人相互覆盖。v0.1 资料升级时只补建当前内容的历史基线，之前被覆盖的正文无法恢复。文档的正文、来源、年度、考试、地区、有效期、资料负责人均随版本保存。

每份资料当前只有一个正式快照：发布未来生效的版本会替换旧版，生效前暂停引用；如需旧版持续服务，可先保存草稿，到生效时再发布。多考试咨询分别记忆各自已明确的年度和地区，新考试缺少背景时先澄清，不拼接其他考试的条件。

## 员工与权限（v0.2）

管理员在“员工与权限”新增账号，设置岗位和至少 12 位的初始密码；不修改既有管理员密码。停用员工、改变岗位或重设密码立即结束其旧登录，系统始终保留至少一名启用的管理员。

| 岗位 | 知识 | 咨询与线索 | 统计 | 员工、分配、导出、企业配置 |
| --- | --- | --- | --- | --- |
| 管理员 | 草稿、审核、发布、回滚 | 全机构 | 全机构 | 可管理 |
| 知识运营 | 草稿、提交审核、历史、检索测试 | 无 | 无 | 无 |
| 客服 | 无 | 全机构接待、跟进 | 全机构 | 无 |
| 课程顾问 | 无 | 仅分配给自己的线索及关联咨询 | 本人范围 | 无 |

线索负责人从启用的员工列表选择，以员工 ID 授权，不能输入任意姓名。旧版文字归属保留供参考，需要管理员重新分配，不会按同名自动开放权限。详情、会话、跟进、列表和统计均在服务端检查范围。

## 课程与班次（v0.3，编号 4）

管理员可新建课程，设置考试、班型、课时和课程说明；为课程维护多个线上、线下或混合班次、地点、开班安排、起止时间、售价和价格有效期。线下及混合授课需要填写地点；价格按整数分保存，界面以元填写。班次有草稿、可报名、停售、已满班和已结束状态，整个课程也可停售。其他岗位只能读取课程。

首次升级会幂等生成与原演示资料一致的 8 个基础班；不会覆盖后续人工维护的数据。机器人直接读取当前课程及班次业务数据。价格过期、尚未生效、停售、满班或结束后，不沿用旧报价；改价和停售也会使旧答案引用失效。普通文档里的历史经营数字不再用于报价，课程类型文件作为参考存档，课程的描述和经营信息请在“课程与班次”维护；考试政策继续按原年度和地区规则检索。课程名称、班型和说明等自由文本不能夹带价格或课时，避免与专用字段冲突。

## 学员档案与跟进（v0.3，编号 5）

“学员档案”是独立档案，不再只是已成交线索列表。可手动新建，或在线索详情中独立建档；同一学员可关联多次咨询，维护多个考试目标、课程需求、目标年度、需求状态和备注。历史已成交线索会逐条独立建档，不按联系方式自动合并。

联系方式相同只提示疑似重复；关联已有学员前须人工确认身份。管理员可填写核验原因并确认合并，原档案保留去向和审计记录；各条咨询的联系方式核验、联系许可保持独立，不因另一条咨询允许联系就恢复已停止联系的请求。误关联可由管理员解除。演示与真实业务记录不能关联或合并。

一个学员和其关联线索使用同一负责人。管理员更改其中一条已关联线索的负责人时，会同步学员及全部关联线索；顾问只能读取本人范围，连续合并的历史档案也同步归属。联系方式由关联留资记录展示，不另复制一份共享授权。

在线索详情设置“下次跟进（北京时间）”，工作台与“跟进待办”会显示提醒；可筛选逾期、今天和待跟进。完成待办会清空下次时间并写入跟进记录。已停止联系或处于已成交／已失效阶段的线索不提醒外呼；普通跟进和售后记录仍保留。

## 列表、导出与统计（v0.3，编号 6）

会话、线索、知识、课程、学员及审计使用服务端分页，页大小可选 20、50、100，取消原 300 会话／500 线索截断。业务列表、CSV 和看板共用授权与日期、考试、负责人、阶段、意向和联系许可筛选。起止日期均包含，按北京时间的创建日期计算；线索关键词支持姓名、负责人、完整手机号或邮箱，联系方式不支持密文部分匹配。

导出沿用当前线索筛选条件，导出全部匹配行，不受当前页大小限制。会话留资率以所选会话中已留资会话数为分子，不把其他创建日期的线索直接相除；阶段和意向按当前状态统计。知识准备情况为全库有效资料数量，咨询和线索统计按业务筛选。列表突出显示“已停止联系”。学员及知识筛选仅展示本资源适用的字段。

当前仍使用 offset 分页；持续新增期间跨页不是冻结快照。课程需求选择器最多载入前 100 门课程，当前演示规模内可用；扩大课程规模时需加检索选择器。当前 CRM 关联、合并和负责人更新按企业串行保护一致性，扩容前应重新评估锁粒度及统计聚合性能。

## 建议体验顺序

1. 登录后台，查看“企业知识库”，选择一份演示课程并使用“检索测试”。
2. 打开官网演示，点击右下角“在线咨询”，询问“公安联考基础班多少钱”。
3. 展开答案来源，检查演示说明与资料版本；继续问“可以试听吗”。
4. 点击“请顾问联系我”，使用合成邮箱测试，主动确认本次联系用途。
5. 在后台“咨询线索”中查看标签证据，更新负责人、阶段和人工等级，添加跟进。
6. 在客服窗口申请转人工，在“咨询会话”接管并回复，查看访客窗口收到消息。
7. 在线索详情独立建档或关联已核实的学员，在“学员档案”维护多次咨询与课程需求；设置下次跟进，在工作台或待办完成。已成交且尚未建档的线索也会独立建档。

规则等级是辅助判断，不是成交概率。系统按完整消息顺序保存多个考试需求：取消不会被“谢谢”等礼貌收尾重新激活；明确重新咨询时重新评估，旧预算和报名信号不会自动恢复。更换考试、同时备考和售后需求分别记录。会话侧栏可查看购买意愿、各项需求、联系许可及消息证据；售后不参与销售等级评分，人工确认的等级不会被自动分析覆盖。联系方式默认待核验，只有人工通过正式渠道核验后才能修改状态。当前没有发送短信、邮件或营销消息。

## 官网嵌入

本地网页可以引用：

```html
<script src="http://localhost:18080/widget.js" defer></script>
```

加载器使用独立 iframe、按点击加载、宿主页存储恢复凭据，并校验跨窗口消息的来源和发送窗口。访客令牌只能读取自己的会话，不依赖第三方 Cookie。公开入口仍需要限流；域名与 CORS 不能代替鉴权。

当前只部署在本机。正式企业官网不能引用开发者的 localhost，需要先部署到可访问的 HTTPS 服务、调整代理 CSP 与来源策略并完成安全验收。首版未实现强域名绑定管理，不能把组件的公开地址当作不可被他站使用的凭据。

## 测试

后端单元及接口测试在临时 SQLite 中运行，明确禁用模型 Key，不产生模型调用费用：

```bash
docker compose run --rm backend python -m pytest tests -q
```

真实 PostgreSQL/Redis/API 冒烟：

```bash
docker compose exec -T backend python - < scripts/smoke.py
```

该测试使用合成信息创建会话和线索，完成后标记演示，不进入默认业务统计。它验证未知问题处理，不额外调用付费模型。真实 DeepSeek 问答需要单独少量联调。

前端本地需要 Node 22；Docker 构建已内置，不要求更改系统 Node：

```bash
cd frontend
npm ci
npm run build
```

关闭“包含演示记录”可以排除合成数据。人工标记为测试的记录同样排除；验收和联调记录应标记为演示。有效咨询指已发送问题或主动提交联系请求的会话；仅打开面板不会增加咨询量。报表按 Asia/Shanghai 日期统计。当前统计查询有首版规模限制，不提供未经核验的解决率、通过率或成交因果结论。

## 数据、权限和恢复边界

- 后台使用 Argon2 密码哈希、随机服务器会话、12 小时过期、HttpOnly Cookie 及写入来源校验。
- 访客使用独立高熵令牌，持久化仅存 HMAC 摘要，7 天后不能恢复旧会话。
- 联系方式使用 Fernet 认证加密，密钥由 `SESSION_SECRET` 派生。**更换该密钥必须先规划解密重加密迁移和会话失效，不能直接删除或随机覆盖。** 备份必须安全保留该密钥。
- 访客明确拒绝继续联系时，记录停止联系状态；需要再次主动提交授权才能重新开启。文档下架、转内部或更新版本后，公众历史、重放和模型上下文不再返回旧引用正文，后台保留审计快照。
- 所有业务对象保留企业标识；当前实现四种员工岗位及对象范围授权，仍为单企业自用，尚未完成多租户 RLS 或 SaaS 商业化隔离验收。
- 核心资料、会话、线索和跟进持久化 PostgreSQL，模型缓存在独立卷。数据库备份可使用 `docker compose exec -T db pg_dump -U zhixing zhixing > backup.sql`；备份含密文及业务内容，应安全存放。
- 已完成本地 PostgreSQL 备份恢复后的升级和并发演练；长期压测、生产恢复目标与 SLA、自动隐私请求处理、完整数据删除生命周期、审计不可篡改和扫描件沙箱解析仍需后续落实。

## 接待、试听、质量与文档任务（v0.4，编号 7–9）

- 接待员工可在顶栏选择在线、暂离、离线。30 秒心跳，90 秒未刷新视为离线；在线状态不承诺即时回复。会话按排队时间展示，员工分别保存已读水位；当前接待人或管理员可转交。转交不改变线索负责人，顾问仍只能接待本人线索或明确转交的匿名咨询。
- 官网客服可先自愿留资，再选择班次和意向时间申请试听。申请为待确认，后台可确认顾问与时间、记录参加或取消；确认会检查当前班次、联系许可和顾问权限。演示申请不会发出真实通知，也不代表真实机构预约。
- “质量与用量”仅管理员可进入。访客可对自己的完整回答评价；未知问题、负反馈生成知识缺口，管理员记录处理结果或创建待审核知识草稿。创建草稿不会自动发布，也不会自动标为已解决。
- 17 条固定评测样本覆盖八类考试课程及政策、未知、否定、售后。生成样本只执行检索与规则分析，不调用付费模型；粘贴实际回答并逐条人工核对，全部标注后才显示本批样本通过率。业务回答质量仍需机构人工验收。
- DeepSeek 调用保存状态、Token、耗时和安全错误分类。管理员自行核对供应商单价后填写人民币 / 百万 Token 单价及日/月预算。只对匹配模型的新调用估算，保留调用时单价；失败或中断且未收到用量时显示未知，无法估价的调用不伪报为免费。预算为站内告警，不自动断流；以供应商账单为准。历史 Token 可在原数据分析查看，v0.4 明细从升级后的调用开始记录。
- 上传文件异步解析成草稿。“文档处理任务”每 5 秒刷新状态、进度、尝试次数与安全失败原因。发布同步原子切换文字切片，独立 `worker` 容器补充向量；向量未完成时文字检索继续可用。失败可手动重试，最多 3 次；进程崩溃的运行任务在 10 分钟租约过期后重新领取。旧租约和旧资料版本不能覆盖当前结果。知识详情可重建索引。

启动全部服务使用 `docker compose up -d --build`，包含后台、worker、网页、PostgreSQL 和 Redis；只对本机开放 18080 端口。
